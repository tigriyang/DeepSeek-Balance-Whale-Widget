# 与上游的关系

本仓库是 [MeteorNOX/DeepSeek-Balance-Whale-Widget](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget)
的 fork，**暂时保持依附，不独立成另一个项目**。

上游是 JavaScript 写的 DSH 网页插件；本仓库是 Swift / AppKit 的 macOS 应用。
两边语言与形态不同，但上游仍在持续迭代，界面、交互、节奏上的改进
对这边有价值。保留 fork 关系，是为了让继承关系可见，也方便持续跟进上游。

## 不做什么

- **不 merge / rebase 上游 main。** 上游推进的是网页插件代码；合进来会把已经废弃的
  JS/HTML 重新带回工作树，冲突通常没有正确的解。
- **不把整个仓库往上游推。** 语言、形态都不同，几百行的整体替换无法审查。
  但**能在上游插件侧解决的改动要回上游**（issue / 小 PR），不要另起炉灶重复造；
  只有 Swift 原生特有的部分才留在这边。
- **不把上游的版本号当自己的版本号。** WhaleFloat 独立发版（`0.2.0-beta.1` 起）；
  上游的 `v0.4.2` 与本仓库的 tag 没有对应关系。
- **不用 GitHub 的 “Sync fork” 手动合并代码。** 这个按钮会把上游的 JS 代码合进来；
  本仓库的 main 有独立提交，点了只会制造合并与冲突。跟进上游用审查 + 手动移植。

## 做什么

- **只按需移植界面与交互修复。** 上游 `assets/`、`lib/` 里与视觉、交互节奏、
  吸附/翻转、气泡排版相关的改动，读 diff 后手写对应实现，或 cherry-pick 能独立成立的小提交。
- **每月看一次上游 UI 提交。** 用 `tools/upstream-review.sh` 列出最近一段时间的
  相关提交；看完把决定记进当日日志。
- **素材与商标按 `NOTICE-ASSETS.md` 处理。** 上游换素材时同步更新来源说明；
  收到权利主张立即替换或移除。

## 协作面

- `origin` 是本仓库（`tigriyang/...`），`upstream` 只 fetch、不 push。
- 上游没有本仓库的写权限，本仓库也没有上游的写权限；两边不会互相推送。
- GitHub 的分叉提示（ahead / behind）只说明提交集合差。本仓库相对上游是 **ahead**；
  将来上游再推进时会出现 behind，那是预期状态，不需要“跟上”。
- 如果本仓库要改名，GitHub 会保留旧地址重定向；改名是为了让「这是另一个应用」
  在搜索结果里一眼可见，而不是切断历史。

## 定位

WhaleFloat 是上游的 **macOS 移植版**，依附于上游，不与之竞争：

- 上游负责网页插件这条线；这边负责 macOS 原生应用。
- 上游的界面/交互改进，定期看、按需移植；能回上游的改动回上游。
- 两边各自发版，但这边不另立门户、不改名脱离 fork 网络。
- 要 DSH 网页插件 → 去上游；要 macOS 独立桌面应用 → 来这里。
